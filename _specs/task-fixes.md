# タスクまわりの不具合修正

## 目的

コード全体を見直して見つかった、タスクのフォームとタスク詳細に関する 2 つの不具合を直す。いずれも小さな修正で、見た目は変えない。ラベルと入力欄の結び付きを正しくし、タスク詳細の作り方をプロジェクト詳細に揃える。

| #   | 不具合                                                                       | 今の影響                                                           |
| --- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1   | タスク追加モーダルとタスク詳細のフォームで、入力欄の `id` が同じ             | タスク詳細でモーダルを開くと、ラベルと入力欄の結び付きがずれる     |
| 2   | タスク詳細（`TaskDetail`）が、表示するタスクの id が変わっても作り直されない | 画面には出ない（タスク詳細どうしを直接行き来するリンクがないため） |

## 対象ページ

- `/tasks/<id>`（タスク詳細。ヘッダーのタスク追加モーダルを開いた状態も含む）
- 全ページ共通のヘッダーのタスク追加モーダル

## 要件

見た目・文言は変えない。

### 1. フォームの入力欄の id が重ならないようにする

- [ ] タスク詳細（`/tasks/<id>`）でヘッダーの「タスクを追加」からモーダルを開いたとき、ページ全体で同じ `id` を持つ要素がない（今はプロジェクト・締切日・ステータス・説明・メモの入力欄と、プロジェクト・ステータスのラベルの `id` が重なる）
- [ ] その状態でモーダルのラベル（プロジェクト・締切日・ステータス・説明・メモ）をクリックすると、背面のタスク詳細ではなく、モーダルの入力欄にフォーカスが移る
- [ ] モーダルとタスク詳細のプロジェクト・ステータスのプルダウンは、それぞれ自分のフォームのラベルで読み上げられる（`aria-labelledby` が自分のフォームのラベルを指す）
- [ ] タスク詳細だけ、モーダルだけで使ったときも、ラベルをクリックすると対応する入力欄にフォーカスが移る（今と同じ）
- [ ] モーダルを開くと、今と同じくプロジェクトのプルダウンにフォーカスが移る

### 2. タスク詳細を、タスクの id ごとに作り直す

- [ ] プロジェクト詳細（`/projects/<slug>`）と同じように、タスク詳細は表示するタスクの id が変わると作り直され、読み込み中の表示から始まる。前のタスクの取得結果で、新しいタスクの表示が上書きされない
- [ ] `/tasks` から `/tasks/<id>` を開いたとき、今と同じく「読み込み中…」のあとにタスクの内容が表示される

## 対象外

- タスクの表（ダッシュボード・`/tasks`）でタスクを更新したときに、プロジェクト一覧（`refreshProjects()`）を取り直すこと。API はプロジェクトの集計（`stats`）を初期データの固定値のまま返し、タスクを変えても計算し直さない（`app/api/` は改変しない）ため、取り直しても表示は変わらない
- データ取得処理（`isLoading`・`error` の管理）の共通化。別の PR で行う
- `RecentProject` と `ProjectCard`、2 つの `Pagination` の共通化。別の PR で行う
- タスク追加モーダルからの API 送信（タスクの作成）。別の PR で行う
- 上の 2 つ以外の不具合の修正（見つけても、この仕様書では直さない）
- 見た目・文言の変更

## 使う API・データ

API の呼び方は変えない。

- `GET /api/v1/users/tasks/{id}`（`shared/api` の `getTask()`）— タスク詳細

## デザイン・補足

- 見た目は変わらないので、Figma はない。PR のスクリーンショットは、変わっていないことの確認として撮る。
- 1 について:
  - 重なっている `id`: `task-project`・`task-project-label`・`task-deadline`・`task-status`・`task-status-label`・`task-description`（`src/_app/layouts/TaskCreateForm.tsx` と `src/_pages/task-detail/ui/TaskDetailForm.tsx`）。`task-title` はモーダルにしかない。
  - モーダルは Radix の Portal で `body` の末尾に描かれるため、同じ `id` があると、ページ側（先にある要素）が使われる。
- 2 について:
  - `app/projects/[slug]/page.tsx` は `<ProjectDetail key={slug} … />` としているが、`app/tasks/[id]/page.tsx` は `key` を付けていない。

- CLAUDE.md の「タスクを作成・更新・削除したら `refreshProjects()` で取り直す」という記述は、集計が計算し直されない実際の動作に合わせて書き直し済み（このブランチに含める）。
