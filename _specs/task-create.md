# タスク作成

## 目的

ヘッダーのタスク追加モーダル（`_specs/task-create-modal.md`）は、現状は「作成」を押しても API に送らずに閉じるだけになっている。これを `POST /api/v1/users/tasks` でタスクを作成するようにし、どのページからでも新しいタスクを登録できるようにする。

## 対象ページ

- `/`（ヘッダーは全ページ共通。PR のスクリーンショットはトップでモーダルを開いた状態と、作成に成功したときの表示、作成に失敗したときのエラー表示を撮る）
- `/tasks`（作成後にその場で一覧を取り直す）

## 要件

- [ ] モーダルの項目・入力チェック（未入力のエラー表示）・閉じ方は今のまま変えない
- [ ] すべて入力して「作成」を押すと、入力した内容で `POST /api/v1/users/tasks` にタスクを作成する
  - [ ] 送る項目は `projectId`・`title`（前後の空白を除いたもの）・`description`・`deadline`・`status`・`kind`（常に `"task"`）
- [ ] 送信中
  - [ ] 「作成」ボタンの文言が「作成中…」になり、ボタンは無効になる。続けて押しても 2 回送られない
  - [ ] 入力欄（プロジェクト・タスク・説明・メモ・締切日・ステータス）も無効になる（送信中に書き換えても送られないため。`TaskDetailForm` の保存中と同じ）
  - [ ] 「キャンセル」・閉じるボタン・Esc・オーバーレイのクリックでモーダルを閉じられる。閉じても作成は続き、結果は下の成功・失敗と同じように知らせる
- [ ] 作成に成功したら
  - [ ] モーダルが開いていれば閉じる
  - [ ] 画面の右下に「タスクを作成しました」と表示して知らせる（`role="status"`）。表示は 5 秒後に自動で消える
  - [ ] いま開いているページのタスク一覧を、ページを開き直さずにその場で取り直す。対象はダッシュボード（`/`）の「タスク」と、タスク一覧（`/tasks`、今のページ番号のまま）。作成したタスクは、ステータスが「未完了」で表示される範囲に入れば一覧に出る
- [ ] 作成に失敗したら
  - [ ] モーダルが開いていれば、閉じずに入力内容を残したまま、フォームに「作成に失敗しました」と表示する（`role="alert"`）。入力欄と「作成」ボタンは元に戻り、もう一度「作成」を押すと再送でき、そのときエラー表示は消える
  - [ ] 送信中にモーダルを閉じていた場合は、成功のときと同じ場所に「タスクの作成に失敗しました」と表示して知らせる（`role="alert"`）
- [ ] デスクトップ表示で崩れない

## 対象外

- 作成後にタスク詳細ページ（`/tasks/[id]`）へ移動すること（API のレスポンスが `data: null` で、作成したタスクの id が返らないため）
- プロジェクトの集計（`stats`）への反映（API が初期データの固定値を返すため。`refreshProjects()` も呼ばない）
- ダッシュボードの統計（`GET /api/v1/users/stats`）の取り直し（同じく固定値のため）
- 作成したタスクを一覧の中で目立たせること、作成したタスクのあるページへ移動すること
- モーダルの見た目・項目の変更、開始日（`startingAt`）の入力、マイルストーン（`kind: "milestone"`）・親タスクの作成
- タスクの編集・削除
- モバイル表示への対応、ダークモード

## 使う API・データ

- `POST /api/v1/users/tasks`
  - swagger.yml の `CreateTask`（`name`・`homePage`・`phone`）は誤っているため、`app/api/v1/users/tasks/route.js` の `POST` と `app/api/datastore/models/task.ts` を参照した。
  - リクエスト: `projectId` でプロジェクトを引き当て、残りの項目はそのままタスクに入る。`title`・`kind`・`status` のどれかがないと 400（`{ message: { message: "Title is required" } }` など）になるため、`kind: "task"` を必ず送る。
  - レスポンス: 成功は 201 で `{ data: null }`（作成したタスクは返らない）。
  - `deadline` は既存データでは `2026-11-02T10:00:00+09:00` 形式だが、`YYYY-MM-DD` でも一覧の並べ替え・表示（`toDateString` などは先頭 10 文字を使う）は動く。
- `src/shared/api/task.ts` に作成の関数はまだない（`getTasks`・`getTask`・`updateTask`・`deleteTask` のみ）。
- プロジェクトの選択肢は今のまま `useProjects()`（`entities/project`）を使う。

## デザイン・補足

- フォーム: `src/_app/layouts/TaskCreateForm.tsx`（今は `handleSubmit` で `onClose()` を呼ぶだけ）。モーダルは `src/_app/layouts/Header.tsx` が `useModal()` と `shared/ui` の `Modal` で開いている。
- 失敗時の文言と出し方は、既存の `TaskRow`（「保存に失敗しました」、`role="alert"`）・`TaskDetailForm`（送信中の無効化、「保存に失敗しました」）に合わせる。エラー文字の色は既存の `.error` と同じ。
- 取り直す一覧は、ダッシュボードが `src/_pages/home/ui/DashboardTasks.tsx`（`useFetch`）、`/tasks` が `src/_pages/tasks/ui/TasksContent.tsx`（取り消し付きの独自の `useEffect`）で、どちらもヘッダー（`_app/layouts`）とは別に取得している。
- 作成した直後のタスクは `children` を持たない（API が補わない）。一覧や詳細で `children` を使っていないことは確認済み。
- 改善 PR の分け方の D に当たる（A は PR #16、B は PR #17、C は PR #18 でマージ済み）。
