# カードとページ送りの共通化

## 目的

ほぼ同じ形のコンポーネントが複数あり、直すときに片方だけ直す漏れが起きやすい。プロジェクトのカード・ページ送り・プロジェクト色の指定・ページ番号の読み取りをそれぞれ 1 つにまとめ、開発者が 1 か所を直せば済むようにする。まとめる際に、ダッシュボードのカードと `/projects` のページ送りの見た目は少し変わる。

## 対象ページ

- `/`（最近のプロジェクトのカード）
- `/projects`（プロジェクトのカード、ページ送り）
- `/tasks`（ページ送り）
- `/projects/[slug]`（プロジェクト詳細のカード。見た目は変えない）

## 要件

### プロジェクトのカード

- [ ] ダッシュボードの「最近のプロジェクト」と `/projects` の一覧は、同じ 1 つのカードのコンポーネントで表示する
- [ ] カードに出す内容は今と同じ: プロジェクト名、締切日（カレンダーのアイコン付き、`YYYY/MM/DD`）、ゴール（`goal`）、あるべき姿（`shouldbe`）、マイルストーン数・タスク数（アイコン付き）、左端のプロジェクト色の帯。カード全体がプロジェクト詳細（`/projects/[slug]`）へのリンク
- [ ] ダッシュボードは今と同じく先頭 3 件、`/projects` は今と同じく 1 ページ 10 件を表示する
- [ ] 見た目は今の `/projects` のカード（`ProjectCard`）に揃える。`/projects` の見た目は変わらず、ダッシュボードのカードが次のように変わる
  - 背景が白（`--color-surface`）になり、余白が上下 16px・左右 20px になる
  - プロジェクト名が 12px・プロジェクト色になる
  - 締切日が 12px・太字なしになり、カレンダーのアイコンが 12px になる
  - ゴールが `--color-text`、あるべき姿が `--color-text-muted` になる
  - 件数の行は、アイコンが 14px、間隔が 12px、上の余白が 8px、色が `--color-text-sub` になる

### プロジェクト色の指定

- [ ] プロジェクト色を CSS 変数 `--project-color` として要素に渡す書き方（今は `{ "--project-color": project.color } as React.CSSProperties` が 4 か所にある）を 1 つにまとめ、4 か所すべてで使う
  - サイドバーのプロジェクト名（`SidebarProject`）、ダッシュボードのカード（`RecentProject`）、`/projects` のカード（`ProjectCard`）、プロジェクト詳細のカード（`ProjectDetailCard`）
  - カードを 1 つにまとめたあとは 3 か所になる
- [ ] サイドバーとプロジェクト詳細の見た目は変わらない

### ページ送り

- [ ] `/projects` と `/tasks` のページ送りは、同じ 1 つのコンポーネントで表示する
- [ ] 見た目は今の `/tasks` のページ送りに揃える。前後への移動は「<」「>」のアイコン（`aria-label` は「前のページ」「次のページ」）、項目の間隔は 16px、ホバー時の背景はなし。`/projects` のページ送りがこの見た目に変わる
- [ ] ページ数が多いときは、先頭・末尾・今のページとその前後だけを並べ、あいだを「…」で省く（今の `/tasks` と同じ。7 ページ以下なら全ページを並べる）
- [ ] 今のページは `aria-current="page"` が付き、`--color-primary` の太字で表示される
- [ ] ページ番号と「<」「>」はリンク（`<a>`）にする。`/tasks` も、今のボタン（押すと `router.push` で移る）からリンクに変わる
- [ ] 1 ページ目では「<」、最終ページでは「>」が押せず、薄い色で表示される（リンクにしない）
- [ ] ページを移ると URL の `page` が変わる。`/tasks` は今と同じく `limit` を保ち、1 ページ目と 20 件はクエリに含めない
- [ ] 1 ページしかないときは、ページ送りを出さない（今の `/tasks` と同じ。`/projects` は初期データが 3 件のため、ページ送りが出なくなる）
- [ ] `/tasks` の表示件数の切り替え・範囲外のページを 1 ページ目に戻す動き・件数の表示は今のまま変えない

### ページ番号の読み取り

- [ ] `/projects` の URL の `page` は、`/tasks` と同じページ番号の読み取り（`parsePage`）で読む。数字以外・0 以下・空のときは 1 ページ目になる
- [ ] `/projects` で全ページ数を超える `page` を指定したときは、今と同じく 1 ページ目を表示する（URL は書き換えない）

## 対象外

- カード・ページ送りへの項目や機能の追加（ページ番号の直接入力、表示件数の切り替えを `/projects` に足すなど）
- サイドバーのプロジェクト一覧・プロジェクト詳細のカードの見た目の変更、これらをプロジェクトのカードにまとめること
- `/projects` を API のページ送り（`page`・`limit`）で取得し直すこと（今のまま `useProjects()` の一覧を画面で 10 件ずつに分ける）
- ダッシュボードのタスク一覧など、ほかの一覧の共通化
- 「プロジェクトを追加」ボタンの実装
- モバイル表示への対応、ダークモード

## 使う API・データ

- API の呼び出しは変えない。プロジェクトは `useProjects()`（`entities/project`）、タスクは `getTasks()`（`shared/api`）のまま。

## デザイン・補足

- 今のカード: `src/_pages/home/ui/RecentProject.tsx`（`.module.scss` に `.root` がない）と `src/_pages/projects/ui/ProjectCard.tsx`。どちらも `<li>` の中の `Link` で、JSX の形はほぼ同じ（違いはクラス名・アイコンの大きさ・CSS）。
- 今のページ送り: `src/_pages/projects/ui/Pagination.tsx`（リンク、省略なし、常に表示）と `src/_pages/tasks/ui/Pagination.tsx`（ボタン、`…` の省略付き、2 ページ以上のときだけ表示）。
- `parsePage` は今は `src/_pages/tasks/lib/params.ts` にあり、`_pages` のスライス同士は import できない（FSD のルール）。
- 色はすべて既存の CSS 変数（`--color-primary`・`--color-text-sub`・`--color-text-muted`・`--color-surface`・`--shadow-card` など）で足りる見込み。
- 改善 PR の分け方の C に当たる（A は PR #16、B は PR #17 でマージ済み。D のタスク作成はこのあと）。
