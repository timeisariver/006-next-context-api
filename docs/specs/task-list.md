# タスク一覧ページ

## 目的

ダッシュボードのタスク一覧は先頭の 20 件までしか表示できず、「すべてのタスクをみる」と「あと X ページ」のリンクは `/tasks` に遷移するが、そのページがまだ無く 404 になる。`/tasks` に、タスクを 1 ページ 20 件ずつ最後まで見られる一覧ページを作る。

## 対象ページ

- `/tasks`（新規）

## 要件

- [ ] `/tasks` を開くと、`GET /api/v1/users/tasks` で取得したタスクが一覧で表示される。
- [ ] ページの左上に「タスク」の見出しが表示される。
- [ ] 見出しの下に、左から「1 / 5」（表示中のページ / 全ページ数）、「表示件数：」のラベルとセレクトボックス、「100 件」（全タスクの件数）が横に並ぶ。この行は、取得中や取得に失敗したときも表示し、まだ分からない数は「-」で表す（例: 「- / -」「- 件」）。表示件数は、取得に失敗したときも変えられる。表示件数を変えた直後は、取得が終わるまで、前の「ページ数」と「全件数」を表示したままにする。

### 表示件数

- [ ] 表示件数のセレクトボックスの選択肢は「20 件」「50 件」「100 件」の 3 つ。初期状態は「20 件」が選ばれている。
- [ ] 表示件数を変えると、その件数で 1 ページ目からタスクが表示し直される。「1 / 5」の全ページ数と、ページ送りのページ番号も、変えた件数に合わせて変わる。
- [ ] 表示件数が URL に反映される（例: `/tasks?page=2&limit=50`）。その URL を直接開いたり、再読み込みしたりしても、同じ表示件数・ページが表示される。`limit` が 20・50・100 以外のとき、または `page` が範囲外・数値でないときは、20 件・1 ページ目として表示される。
- [ ] 「100 件」には、API の `totalCount`（全タスクの件数）が表示される。表示件数を変えても変わらない。

### 一覧

- [ ] 一覧は表で、ダッシュボードのタスク一覧と同じく、左から「タスク」「プロジェクト」「ステータス」「期限日」の列と、最後に→アイコンの列が並ぶ。先頭に見出し行があり、→アイコンの列の見出しは空にする。
- [ ] 「タスク」にはタスクのタイトルが表示される。
- [ ] 各行の最後のセルの→アイコンは、そのタスクへのリンク（`/tasks/<タスクの id>`）になっている。
- [ ] タスクは期限が近い順（期限日の昇順）に並ぶ。
- [ ] 取得中は「読み込み中…」と表示される（「最近のプロジェクト」と同じ表示）。
- [ ] 取得に失敗したときは「読み込みに失敗しました」と表示される（「最近のプロジェクト」と同じ表示）。
- [ ] タスクが 0 件のときは、「タスクはありません」と表示される。

### ページ送り

- [ ] 1 ページに、表示件数で選ばれた件数（20・50・100 件）ずつ表示される。
- [ ] 一覧の右下に、ページ送りが表示される。左から「<」の矢印、ページ番号（1, 2, 3 …）、「>」の矢印が横に並ぶ。
- [ ] ページ番号は、全ページ数が 7 以下なら、全ページぶんが 1 から順に並ぶ。8 以上のときは、先頭・末尾・表示中のページとその前後だけを並べ、あいだは「…」で省く（例: 1 … 4 5 6 … 10）。表示中のページの番号だけが、太字・緑の文字（`--color-primary`）で表示される。
- [ ] ページ番号を押すと、そのページのタスクが表示される。
- [ ] 「<」を押すと前のページ、「>」を押すと次のページが表示される。1 ページ目では「<」、最後のページでは「>」は押せない（薄い色で表示する）。
- [ ] 全ページが 1 ページ以内のときは、ページ送りは表示されない（「1 / 1」と件数の表示は残る）。
- [ ] 表示中のページが URL に反映される（例: 2 ページ目は `/tasks?page=2`）。
- [ ] ダッシュボードの「あと X ページ」から `/tasks` を開くと、1 ページ目が表示される。

### 編集

- [ ] 「プロジェクト」「ステータス」「期限日」は、ダッシュボードのタスク一覧と同じ操作で変更でき、`PATCH /api/v1/users/tasks/<タスクの id>` で保存される（選択肢、期限日の入力方法、保存中と失敗時の表示も同じ）。
- [ ] ステータスや期限日を変更しても、ページを再読み込みするまでは一覧の今の位置に残る（行が急に消えたり並び替わったりしない）。

## 対象外

- ステータスの絞り込み（「完了」「アーカイブ」のタスクの表示）、並び替え、キーワード検索の UI。このページには「未完了」のタスクだけが表示され、完了・アーカイブしたタスクは再読み込みすると一覧から消える（別の仕様書であとから作る）
- タスクの追加・削除
- プロジェクト・ステータス・期限日以外の項目の編集
- 「タスク詳細ページ」（`/tasks/<タスクの id>`）の作成（`docs/specs/task-detail.md` で別に作る。それまでリンク先は 404 になる）
- ダッシュボードの変更
- モバイル向けのレイアウト

## 使う API・データ

- `GET /api/v1/users/tasks`（仕様は `/api/v1/spec` を参照）
  - クエリ: `limit`（表示件数で選ばれた件数。初期状態は 20）、`page`（1 始まり）、`status`（`scheduled` / `completed` / `archived`。指定しない場合は `scheduled` のみ）
  - レスポンス: `{ data: Task[], pageInfo: PageInfo }`。`pageInfo` は `page` / `limit` / `totalCount` / `hasNext` / `hasPrevious`。全ページ数は `totalCount` と `limit` から求める。
  - 結果は期限（`deadline`）の昇順で返る。
- `PATCH /api/v1/users/tasks/{id}`（タスクのプロジェクト・ステータス・期限日の変更）。リクエストとレスポンスの形は `docs/specs/dashboard-task-list.md` と同じ。
- 既存の `src/shared/api/task.ts` の `getTasks()` / `updateTask()` と `Task` / `PageInfo` 型は、`feature/dashboard-task-list`（PR #2）で追加されたものを使う。
- プロジェクトの選択肢には、`useProjects()`（`GET /api/v1/users/projects`）のプロジェクト一覧を使える。

## デザイン・補足

- ページ送りは添付画像（`< 1 2 3 4 5 >`）の見た目にする。「<」「>」は細めの矢印アイコンで、ページ番号は文字だけ（枠や背景なし）。表示中の番号は太字の緑、ほかの番号は `--color-text-sub` 相当の控えめな文字色。
- 見出しと件数の表示は添付画像（「タスク」の下に `1 / 5　表示件数： 20 件 ⌄　100 件`）の見た目にする。見出しは控えめな文字色、「1 / 5」「表示件数：」「100 件」は小さめの補足色の文字（`--color-text-sub` 相当）。セレクトボックスは枠なしで、選択中の件数は本文色。
- 一覧の見た目は、デザインの指定がない。ダッシュボードのタスク一覧（`src/_pages/home/ui/TaskTable.tsx`）と、既存ページの見た目（余白・文字の大きさ・色・枠線）に合わせ、色や影は `src/_app/styles/globals.scss` の CSS 変数を使う。
- 表の行（`TaskRow`）と期限日のセル（`DeadlineCell`）は、今はダッシュボード（`src/_pages/home/ui/`）にある。FSD ではページ（スライス）どうしで import できないため、両方のページから使うには、置き場所を移す必要がある。
- 読み込み中・エラーの表示は `src/_pages/home/ui/RecentProjects.tsx` に揃える。
