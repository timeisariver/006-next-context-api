# ダッシュボードのタスク一覧

## 目的

ダッシュボード（`/`）の「タスク一覧」は見出しと「すべてのタスクをみる」リンクだけで、中身が空になっている。ここに API から取得したタスクを表示し、ユーザーがダッシュボードを開いただけで、取り組むべきタスクを確認できるようにする。

## 対象ページ

- `/`（ダッシュボード）

## 要件

- [ ] ダッシュボードの「タスク一覧」の枠内に、`GET /api/v1/users/tasks` で取得したタスクが一覧で表示される。表示するのは API の既定どおり、ステータスが `scheduled`（未完了）のタスクだけ。
- [ ] 一覧は表で、左から「タスク」「プロジェクト」「ステータス」「期限日」の列と、最後に→アイコンの列が並ぶ。先頭に見出し行があり、→アイコンの列の見出しは空にする。
- [ ] 「タスク」にはタスクのタイトルが表示される。
- [ ] タスクは期限が近い順（期限日の昇順）に並ぶ。
- [ ] 取得中は「読み込み中…」と表示される（「最近のプロジェクト」と同じ表示）。
- [ ] 取得に失敗したときは「読み込みに失敗しました」と表示される（「最近のプロジェクト」と同じ表示）。
- [ ] タスクが 0 件のときは、「タスクはありません」と表示される。

### ページ数とリンク

- [ ] タスクは先頭の 20 件まで表示される。
- [ ] 「タスク一覧」の枠の左下に「あと X ページ」という文字リンクが表示される（X は 20 件を 1 ページとしたときの残りのページ数。例: 全 45 件なら「あと 2 ページ」）。
- [ ] 「あと X ページ」を押すと `/tasks` に遷移する（右上の「すべてのタスクをみる」と同じ遷移先）。
- [ ] タスクが 20 件以下（残りが 0 ページ）のときは、「あと X ページ」は表示されない。
- [ ] 各行の最後のセルの→アイコンは、そのタスクへのリンク（`/tasks/<タスクの id>`）になっている。

### プロジェクトの変更

- [ ] 「プロジェクト」はセレクトボックスで、タスクが属するプロジェクトが選ばれた状態で表示される。選択肢は全プロジェクトの名前（サイドバーと同じプロジェクト一覧）。
- [ ] 別のプロジェクトを選ぶと、`PATCH /api/v1/users/tasks/<タスクの id>` でタスクのプロジェクトが変更され、ページを再読み込みしても変更後のプロジェクトが選ばれている。

### ステータスの変更

- [ ] 「ステータス」はセレクトボックスで、タスクの今のステータスが選ばれた状態で表示される。選択肢は「未完了」（`scheduled`）・「完了」（`completed`）・「アーカイブ」（`archived`）の 3 つ。
- [ ] 別のステータスを選ぶと、`PATCH /api/v1/users/tasks/<タスクの id>` でタスクのステータスが変更される。
- [ ] 「未完了」以外に変えたタスクも、ページを再読み込みするまでは一覧に残る（行が急に消えない）。再読み込みすると一覧から外れる。

### 期限日の変更

- [ ] 期限日は `2026/11/04` のように、年 4 桁・月日 2 桁（1 桁のときは 0 を付ける）をスラッシュで区切って表示される。
- [ ] 期限日の右側にカレンダーアイコンが表示される。
- [ ] 期限日をクリックすると入力欄になり、`2026/11/04` の形で日付を入力できる。Enter を押すか入力欄の外をクリックすると、入力した日付が `PATCH /api/v1/users/tasks/<タスクの id>` でタスクの期限として保存される。Esc を押すと、保存せずに元の表示に戻る。
- [ ] 入力が日付として正しくないとき（`2026/13/40` など）や空のときは、保存せずに元の期限日に戻る。
- [ ] カレンダーアイコンをクリックするとブラウザ標準の日付選択（`<input type="date">`）が開き、選んだ日付が `PATCH /api/v1/users/tasks/<タスクの id>` でタスクの期限として保存される。
- [ ] 期限日を変更したあと、ページを再読み込みしても変更後の期限日が表示される。
- [ ] 期限日を変更しても、一覧は並べ直さず今の位置に残る（再読み込みすると期限順に並ぶ）。

### 保存中と失敗時（プロジェクト・ステータス・期限日共通）

- [ ] 保存している間、変更した行のそのセルのセレクトボックスまたは期限日は操作できない。
- [ ] 保存に失敗したときは、そのセルを変更前の値に戻し、行の近くに「保存に失敗しました」と表示する。

## 対象外

- プロジェクト・ステータス・期限日以外の項目（タイトル・説明など）の編集、タスクの追加・削除などの操作
- ダッシュボード上でのページ送り（21 件目以降の表示）
- 遷移先の `/tasks` ページの作成（別の仕様書で作る。それまでリンク先は 404 になる）
- →アイコンのリンク先 `/tasks/<タスクの id>`（タスクの詳細ページ）の作成（それまでリンク先は 404 になる）
- →アイコン以外（行全体やタスク名）を押したときの遷移
- 並び替え・絞り込みの UI
- 「進捗サマリー」など、タスク一覧以外のダッシュボードの項目

## 使う API・データ

- `GET /api/v1/users/tasks`（仕様は `/api/v1/spec` を参照）
  - クエリ: `limit`（既定 20）、`page`（既定 1）、`status`（`scheduled` / `completed` / `archived`。既定は `scheduled` のみ）
  - レスポンス: `{ data: Task[], pageInfo: PageInfo }`
  - `Task` の主な項目: `id`, `title`, `description`, `status`, `deadline`, `project`（`Project`）, `parent`, `children`。swagger.yml には無いが、データには `kind`（`task` / `milestone`）も含まれる。
  - 結果は期限（`deadline`）の昇順で返る。
- `PATCH /api/v1/users/tasks/{id}`（タスクのプロジェクト・ステータス・期限日の変更）
  - リクエスト: `{ "projectId": "<プロジェクトの id>" }`、`{ "status": "completed" }`、`{ "deadline": "2026-11-04" }` のいずれか
  - API の `deadline` は `2026-10-28T12:34:56+09:00` のような文字列（初期データは `dayjs().format()` で作られている）。一覧の並び替えは先頭の `年-月-日` だけを見ているため、保存するときは `2026-11-04` の形（年-月-日）で送ればよい。
  - レスポンス: `{ data: Task }`（変更後のタスク）
  - swagger.yml の `UpdateTask` は中身が別物（`name` / `homePage` / `phone`）になっているため、リクエストの形は `app/api/v1/users/tasks/[id]/route.js` と `app/api/datastore/models/task.ts` の `assign()` で確かめた。`projectId` のほか `title` / `description` / `status` / `deadline` を受け付ける。
  - 変更はサーバーのメモリ上に保存されるため、開発サーバーを再起動すると元に戻る。
- プロジェクトの選択肢には、`useProjects()`（`GET /api/v1/users/projects`）のプロジェクト一覧を使える。

## デザイン・補足

- 表示先は `src/_pages/home/ui/TaskTable.tsx` の空の `.content`。見出し（`DashboardHead`）と「すべてのタスクをみる」（`MoreLink`）は既存のまま使う。
- 読み込み中・エラーの表示は `src/_pages/home/ui/RecentProjects.tsx` に揃える。
- デザインの指定はない。「最近のプロジェクト」など既存のダッシュボードの見た目（余白・文字の大きさ・色・枠線）に合わせ、色や影は `src/_app/styles/globals.scss` の CSS 変数を使う。
