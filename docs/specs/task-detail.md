# タスク詳細ページ

## 目的

ダッシュボードのタスク一覧の→アイコンから開く、タスク 1 件ぶんの個別ページを作る。タスクのタイトルと作成・更新日時を確認し、プロジェクト・締切日・ステータス・説明・メモを 1 画面で編集できるようにする。

## 対象ページ

- `/tasks/<タスクの id>`（新規）

## 要件

- [ ] `/tasks/<タスクの id>` を開くと、`GET /api/v1/users/tasks/<タスクの id>` で取得したタスクの詳細が表示される。
- [ ] 取得中は「読み込み中…」と表示される（ダッシュボードの「最近のプロジェクト」と同じ表示）。
- [ ] 取得に失敗したとき、または存在しない id のときは「読み込みに失敗しました」と表示される。

### 表示

- [ ] 上部の左にタスクのタイトルが見出しとして表示される。
- [ ] タイトルの下に「作成日時: 2026/10/21　更新日時: 2026/10/21」の形で、作成日と更新日が表示される（年 4 桁・月日 2 桁をスラッシュで区切る）。
- [ ] 上部の右にゴミ箱アイコンが表示される。
- [ ] 見出しの下に、上から「プロジェクト*」「締切日*」「ステータス」「説明・メモ」の 4 項目がラベル付きで並ぶ。「プロジェクト」「締切日」のラベルには赤系の `*`（必須）が付く。
- [ ] 「プロジェクト」はセレクトボックスで、タスクが属するプロジェクトが選ばれた状態で表示される。選択肢は全プロジェクトの名前（サイドバーと同じプロジェクト一覧）。
- [ ] 「締切日」は `<input type="date">` で、タスクの期限日が入った状態で表示される。
- [ ] 「ステータス」はセレクトボックスで、タスクの今のステータスが選ばれた状態で表示される。選択肢は「未完了」（`scheduled`）・「完了」（`completed`）・「アーカイブ」（`archived`）の 3 つ。
- [ ] 「説明・メモ」は複数行の入力欄（`textarea`）で、タスクの説明が入った状態で表示される。説明が空のときはプレースホルダー「タスクの説明・メモ」が表示される。
- [ ] 入力欄の下に、幅を半分ずつに分けた緑の「更新」ボタンと濃紺の「リセット」ボタンが横に並ぶ。
- [ ] その下に、左向き矢印アイコン付きの緑の文字リンク「戻る」が表示される。押すと `/tasks`（タスク一覧ページ）に遷移する。

### 更新・リセット

- [ ] 「更新」を押すと、入力中のプロジェクト・締切日・ステータス・説明が `PATCH /api/v1/users/tasks/<タスクの id>` で保存される。ページを再読み込みしても保存した内容が表示される。
- [ ] 保存が成功したら、画面の「更新日時」が保存後の値に変わる。
- [ ] 保存している間は、「更新」ボタンと各入力欄は操作できない。
- [ ] 保存に失敗したときは、入力内容はそのまま残し、「保存に失敗しました」と表示する。
- [ ] 締切日が空のときは、「更新」を押しても保存されない。
- [ ] 「リセット」を押すと、入力中の内容が捨てられ、最後に保存した（または最初に読み込んだ）値に戻る。

## 対象外

- タイトルの編集、親タスク・子タスクの表示や編集
- ゴミ箱アイコンを押したときの削除の動作（アイコンの表示までを作る）
- `/tasks`（タスク一覧ページ）の変更（`feature/task-list`（PR #5）で作成済み。「戻る」の遷移先として使うだけ）
- 入力途中の内容を保存せずにページを離れるときの確認ダイアログ
- 他のタスクへ移動する操作（前へ・次へなど）
- モバイル向けのレイアウト

## 使う API・データ

- `GET /api/v1/users/tasks/{id}`（仕様は `/api/v1/spec` を参照）
  - レスポンス: `{ data: Task }`。存在しない id は 404。
  - `Task` の主な項目: `id`, `title`, `description`, `status`, `deadline`, `createdAt`, `updatedAt`, `project`（`Project`）。`createdAt` / `updatedAt` は `2026-10-21T12:34:56+09:00` のような文字列。
- `PATCH /api/v1/users/tasks/{id}`
  - リクエスト: `{ "projectId": "...", "deadline": "2026-11-04", "status": "scheduled", "description": "..." }`（`app/api/v1/users/tasks/[id]/route.js` と `app/api/datastore/models/task.ts` の `assign()` で確かめる。swagger.yml の `UpdateTask` は誤り）。
  - レスポンス: `{ data: Task }`（変更後のタスク）
  - 変更はサーバーのメモリ上に保存されるため、開発サーバーを再起動すると元に戻る。
- 既存の `src/shared/api/task.ts` の `Task` 型と `updateTask()` は、`feature/dashboard-task-list`（PR #2）で追加されたものを使う。このブランチは PR #5（`feature/task-list`）の上に積んでおり、一覧の→アイコンから `/tasks/<タスクの id>` に遷移できる。1 件取得の関数、`createdAt` / `updatedAt` の型、`UpdateTaskBody` への `description` の追加は、この機能で足す。
- プロジェクトの選択肢には、`useProjects()`（`GET /api/v1/users/projects`）のプロジェクト一覧を使える。

## デザイン・補足

- 添付画像（タスク 100 の詳細ページ）の見た目に合わせる。画像はコンテンツ領域だけで、サイドバーなどの外枠は既存のレイアウトのままにする。
  - 見出しは太字・やや大きめ、作成・更新日時は小さい補足色の文字。ゴミ箱アイコンは見出しの右端。
  - ラベルは見出しより小さい文字。項目どうしの間は広めの余白を取る。
  - セレクトボックス・日付入力・`textarea` は、枠線なしの白い面に薄い影の付いた角丸のボックスで、背景より手前に浮いて見える。→ `--color-surface` と `--shadow-card`、背景は `--color-background` に当たる。セレクトボックスは右端に下向きの矢印（`⌄`）。
  - 「更新」ボタンは緑の塗り・白文字 → `--color-primary` に近い。画像の緑（明るい黄緑寄り）と一致するかは要確認。
  - 「リセット」ボタンは濃紺の塗り・白文字・影付き。`globals.scss` に当たる CSS 変数はない（既存の変数で代用できないか確認し、なければ追加する）。
  - 「戻る」リンクは緑の文字と左向き矢印。→ `--color-primary`。
  - 必須の `*` は赤系。`globals.scss` に当たる CSS 変数はない。
- ページの見出しや余白は、既存のダッシュボード（`src/_pages/home/ui/`）に合わせる。`src/_pages/home/ui/DeadlineCell.tsx` の日付の整形など、流用できるものは流用する。
- 画像のデザインは Figma ではなく添付画像のみ。
