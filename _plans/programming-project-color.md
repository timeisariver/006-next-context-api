# プログラミングプロジェクトの色の修正 実装プラン

- 仕様書: [\_specs/programming-project-color.md](../_specs/programming-project-color.md)
- ブランチ: `feature/programming-project-color`

## 方針

原因は API の初期データ（`app/api/datastore/index.ts`）にある、プログラミングの `color: "#00008c60"` の誤りである。フロントエンド（`src/`）は `project.color` を `--project-color` にそのまま渡して描いているだけなので変更しない。初期データの 1 行を `#00008c99` に直せば、ダッシュボード・`/projects`・`/projects/programming`・サイドバーのすべてに反映される。

`app/api/` は改変禁止なので、今回だけの例外であることを `CLAUDE.md` と `docs/architecture.md` に書き足す。変更は 3 ファイルとも小さく互いに関係するため、1 タスクにまとめる。

## タスク

### 第 1 段階

#### タスク 1: 初期データの色を直し、例外をドキュメントに書く

- 目的: プログラミングプロジェクトの色を本来の `rgba(0, 0, 140, 0.6)` にし、`app/api/` を改変した理由を残す。
- 担当範囲:
  - `app/api/datastore/index.ts`（プログラミングの `color` を `"#00008c60"` から `"#00008c99"` に変える。ほかの行は変えない）
  - `CLAUDE.md`（「ディレクトリ構成」の `app/api/` を改変しない旨の行）
  - `docs/architecture.md`（「その他のルール」の `app/api/` を改変しない旨の行）
- 要件:
  - API の初期データで、プログラミングプロジェクトの `color` が `#00008c99`（= `rgba(0, 0, 140, 0.6)`）になる。`app/api/` の変更はこの 1 行だけにする。
  - ダッシュボードの「最近のプロジェクト」で、プログラミングのカード左側の線が `rgba(0, 0, 140, 0.6)` で表示される。
  - `/projects` のプログラミングのカード左側の線が `rgba(0, 0, 140, 0.6)` で表示される。
  - `/projects/programming` のプロジェクト詳細カード左側の線が `rgba(0, 0, 140, 0.6)` で表示される。
  - サイドバーのプログラミングの丸印が `rgba(0, 0, 140, 0.6)` で表示される。
  - 英語・プライベートの色は変わらない。
  - `CLAUDE.md` と `docs/architecture.md` の、`app/api/` を改変しないという記述に、この初期データの修正だけは例外であることを書き足す。
- 公開 API: なし

## 判断した点

- フロントエンドのコードは変更しない。表示の 4 か所はどれも `project.color` をそのまま使っているため、データを直すだけで要件を満たせる。
- タスクは分けずに 1 件にした。変更が 3 ファイル・数行で、並列にする利点がないため。
- 例外の書き方は、既存の「改変しない」の行の後ろに、例外の対象（`app/api/datastore/index.ts` のプログラミングの `color`）と理由（初期データの誤りで、配布元に報告済み）を書き足す形にする。ルール自体は残す。
- 初期データはサーバーのメモリに読み込まれるため、表示を確認するときは開発サーバーを再起動する。
